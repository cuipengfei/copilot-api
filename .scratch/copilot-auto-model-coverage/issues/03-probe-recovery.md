# 03: 探测失败时保持服务可用

Status: ready-for-human
Blocked by: 02 启动时发现更多模型

**What to build:** 八个探测点分别维护进度。启动等待有上限，已成功的配对立即可用；失败点在服务开始接收请求后继续补采，不影响其他探测点或普通请求。

## Acceptance criteria

- [x] 任一探测点失败后，其余探测点仍能完成尝试；服务启动不会因上游持续故障无限等待。
- [x] 网络失败和上游 5xx 从 1 秒起按随机退避间隔重试，间隔上限为 30 秒；429 优先遵守 `Retry-After`。
- [x] `/auto` 返回 401/403 时暂停同一实例相同凭据的重复探测，凭据变化后恢复；持续的请求格式类 400 记录为待处理问题，不反复发送相同请求。
- [x] 后台补采成功后，实际模型 ID 可被后续请求命中；失败报告提供状态和未完成数量，不输出令牌或抽样代码。
- [ ] 启动等待、状态分类与重试节奏具有可重复的验证方式；真实上游请求须先取得授权。

**规格：** [Copilot Auto 模型覆盖与会话迁移](../spec.md)
